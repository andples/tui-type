# ttyp

Monkeytype-style TUI typing test in Rust (ratatui + crossterm). Binary: `ttyp`.

Cargo workspace: the root package is the `ttyp` binary (so `cargo install --path .`,
`cargo build --release` and `scripts/release.sh` keep working); `crates/ttyp-core` is
the UI-free core shared with the server; `crates/ttyp-server` is the online server.

## Commands

```sh
cargo test --workspace                       # unit tests (core is UI-free)
cargo clippy --workspace --all-targets -- -D warnings
cargo fmt
cargo run                                    # dev build, real config dirs
cargo run -- --config-dir /tmp/c --data-dir /tmp/d   # sandboxed run
```

Server: `cargo run -p ttyp-server` (env `TTYP_BIND`, `TTYP_DB`, `RUST_LOG`; see `crates/ttyp-server/README.md`). Its tests use an in-memory SQLite and a mocked GitHub API; no network.

Headless manual check: `tmux new -d -s t -x 100 -y 28 "target/release/ttyp --config-dir X --data-dir Y"`,
then `tmux send-keys -t t -l 'text'` and `tmux capture-pane -t t -p`.

## Layout

- `crates/ttyp-core/src/test/` — engine (state machine), generator (`WordGenerator` trait), metrics, mode. No UI. Re-exported as `ttyp::test`.
- `crates/ttyp-core/src/language/` — language registry: built-ins via `include_str!` from `crates/ttyp-core/assets/languages/`, user files in the config dir override by name. Re-exported as `ttyp::language`.
- `crates/ttyp-core/src/boards.rs` — the leaderboards as data: `BOARDS` lists every board (`BoardSpec`: wire `id`, `label`, `Period` daily/all-time, `rule` = `api::Board` first/best, `columns` of `Stat`). The server serves any of them at `GET /boards/{id}?<Target::query>` from one query (`leaderboard::board_cte(rule, &Scope)`; `/leaderboard/{daily_id}` stays for pre-2.1.2 clients); `following=true` cuts any board to the caller and who they follow (`leaderboard::Circle`, `f` on the screen, `BoardView::following`), and submissions carry `following_first`/`following_best`; the client's leaderboard screen has one page per `periods()` (`a` cycles) and one pane per `on(period)` board, columns drawn from the spec.
- `src/command/` — command specs + parser (`mod.rs`), palette/fuzzy state (`palette.rs`).
- `src/config/` — `Config` (TOML, `#[serde(default)]`), `Paths` (XDG). Settings files are shared (dotfiles, sync), so `edit.rs` keeps what this version doesn't know: `parse_with_unknown` (serde_ignored) lists the keys a type ignored, and `merge_toml` saves by editing the existing file with toml_edit (sets every serialized key, removes known keys no longer written such as the `celebrate` alias, leaves unknown keys and all comments/order; a missing or unparsable file is written plainly). `Config::save` and `ProfileRegistry::save` both go through it. An unknown key in `config.toml` is a startup warning every start ("unknown setting `x` (kept; …)").
- `src/theme/` — theme registry: built-ins via `include_str!` from `assets/themes/`, user files in config dir override by name.
- `src/catalog/` — installable languages and themes. Only `english`, `english_1k` and the `default` theme are compiled in (`is_builtin` on each registry); the rest live in `catalog/` at the repo root (`languages/`, `themes/`, and `index.toml` listing language word counts and every theme in full, for preview before install). `Source` fetches from `Config::catalog` (default `BUILT_IN_CATALOG`, raw GitHub `main`; `TTYP_DEFAULT_CATALOG` at build time; a local dir also works; `""` turns it off), `install`/`uninstall` write/remove files in the config dirs; each index language carries a `sample` (`catalog::sample`, `SAMPLE_WORDS` spread through the list) for the install screen's typing-style demo under the list (`ui::catalog::demo_lines`: the highlighted language's words, or the current language's in the highlighted theme), `worker.rs` (`Fetcher`) runs downloads off the UI thread like `online::worker`, `menu.rs` is the `:install` screen state. `App::install_missing` installs a configured-but-missing language/theme at startup (skipped when `server = ""`). Language modules (`modules.rs`: `ModuleRegistry`, `word_pool`, `language_key`; files in `languages/<language>/<module>.toml`, listed in the index entry's `modules`) and `Language::trim` (`trim_syntax` setting) are documented in `docs/language-modules.md`; the checklist is `module_menu.rs` + `ui::modules` + `app/modules.rs` (`Screen::Modules`). Runs with modules are recorded as `App::language_key` (`code_python+numpy`). The code languages and their modules are generated by `scripts/code-languages.py`.
- `src/profile/` — profiles, called "configs" everywhere the user sees them (`:config`, the "configs" screen; `:profile` is an alias of `:user` since 1.7): `ProfileSettings` (every `Config` field optional, stored as `profiles/<name>.toml`), `SettingKey` (one per setting, generated by the `settings!` macro), `ProfileRegistry` (load/save/activate/reconcile), `menu.rs` (list + editor state). Active names live in `Config::profiles`; invariant: active profiles are pairwise disjoint and each matches the config — `activate` drops overlapping ones, `App::save_config` reconciles after manual changes. `ProfileSettings` is not `deny_unknown_fields`: unknown keys (a setting from a newer ttyp) are ignored, logged once per run (`note_unknown`), kept on save, and don't count in `matches`/`overlaps`. A file that's there but doesn't load is in `ProfileRegistry::broken` (`load_error`): `activate` refuses it without touching the config, `reconcile` keeps it in the active list (it can't be checked), and its name can't be reused.
- `src/stats/` — `StatsStore` trait, `LocalJsonlStore`, `Summary`. `validity.rs` decides whether a run counts (`check`: afk = `AFK_SECS` zero-key seconds in a row, raw under `MIN_RAW`, accuracy under `MIN_ACC`); the reason is `TestRecord::invalid` (schema 3), and `counts()` keeps such runs out of `personal_best`, pace, `Summary` and `Activity` while the history table marks them `✗`. `activity.rs` is the stats screen's activity view, pure over `TestRecord`s with the time zone and "today" passed in: `Activity` (tests per local day, current/longest streak, totals, best day, `trend` of daily average wpm), `level` (calendar shade 0–4), `calendar_start`, `month_labels`, `spark_levels`. `App` rebuilds `App::activity` on `Action::ShowStats`; `ui::stats` draws the calendar (squares shaded with `style::mix` between theme colours), the streak line and the 30-day sparkline, dropping the calendar and then those lines when the table would get too short.
- Online defaults: `BUILT_IN_SERVER` / `BUILT_IN_GITHUB_CLIENT_ID` in `src/config/mod.rs` are the public server and OAuth App id (owner's decision, 2026-09-29: the hostname is public; the Cloudflare/tunnel tokens are still secret), overridable per build with `TTYP_DEFAULT_SERVER` / `TTYP_DEFAULT_GITHUB_CLIENT_ID`. `App::new` writes them into a config that doesn't name `server`; `server = ""` means offline.
- `src/online/` — optional online play, built only when `server` is set in the config: `client.rs` (blocking ureq calls to the server API), `device.rs` (GitHub device flow behind a `Form` trait so it's testable), `worker.rs` (`Online`: one thread per `Request`, replies come back as `RemoteEvent` over a channel; the event loop drains it and polls every 50 ms while something is in flight), `board.rs` (leaderboard screen state, UI-free), `user.rs` (profile screen state), `queue.rs` (unsent daily results), `token.rs` (0600 token file). Profiles: server `crates/ttyp-server/src/profile.rs` (`GET /users/{login}`, `GET`/`POST /account`), public by default (`users.public = 1`; migration 0003 flipped existing accounts, owner's decision 2026-10-01), hidden with `:account public off`. Players: server `crates/ttyp-server/src/players.rs` (`GET /users?q=` search of public profiles, `GET`/`POST /follows` one-way follows, migration 0004), each row an `api::PlayerSummary` (bests on `MEDAL_DAILIES`, `Badges`, `following`); client `players.rs` (`PlayersView`: search and following tabs, paged search with stale replies dropped; `Follows`: the follow list sorted by last profile view, views in `Paths::views_file`, the 10 most recent feed `Completions::follows` for `:follow`/`:unfollow`).
- `src/app/` — `App`, `Action` enum, key→action mapping, event loop (it handles every input event already waiting before drawing once, and a `Tick` that leaves the typing screen's `ClockView` — HUD text, pace caret — as last drawn draws nothing; `tests.rs` builds an `App` over scratch dirs, `bench.rs` is the by-hand frame-cost benchmark: `cargo test --release --lib frame_cost -- --ignored --nocapture`). `online.rs` (login, `:daily`, submissions), `board.rs` (leaderboard + graph), `user.rs` (profiles, `:account`), `players.rs` (`:search`, `:follow`, `:unfollow`, `Screen::Players`; the follow list is fetched at start and on login), `catalog.rs` (`:install`) and `profiles.rs` (config profiles) hold each screen's behaviour. `splash.rs` is the landing screen (`Screen::Splash`, on at start unless `splash = false`, config-file/`:set` only): `Splash` times the logo intro from an `Instant` (`frame_at`, `next_change_at`, which `poll_timeout` wakes on until it's done), `SplashMenu` picks the keys from the online state, and `leaves_splash` lists the actions that first switch to the typing screen, so the first key lands where it was meant. The menu rows (`SplashItem`) carry a `SplashChoice`; `Splash::selected` is the highlight (`↑`/`↓`), `enter` runs it (`App::splash_choice`), `l`/`d`/`b` are shortcuts, any other letter just goes to the words, untyped. `Action::Daily` opens the command line on `daily ` so the modes are listed. `idle.rs` is its screensaver (`Screensaver`): after 5 s without a key a ghost types random words in the typing font `IDLE_GROW` sizes up (`ui::splash::idle_size`; real-font `ImageLine`s from `splash::render` when `gfx.metrics` allows, else the typing screen's cells); a key while it types is `Action::IdleWake` (swallowed) and crumbles that frame (`ui::splash::draw_idle`; with images each letter falls as its own `ImageLine`), then the landing is back. Any other action on the landing screen restarts the wait; `poll_timeout` wakes for it only while `idle_allowed`. `idle::HOME_AFTER` (30 s without a key, `App::last_input`) sends any other screen back to the landing screen via `App::go_home` while `home_allowed` (splash on, no running test, slider, login, catalogue or config menu). `celebrate.rs` is the new-best confetti (`pb_effect` setting, `config::PbEffect` = both / confetti / trophy / off, profile-able; reads the old `celebrate` bool via a serde alias; the trophy is `ui::results::render_trophy`): `Celebration` rolls its sparks from a seed, `frame_at` places them relative to the "new best" text, `next_change_at` drives `poll_timeout` while `Screen::Results` shows it; it lives in `Outcome::celebration`, so a restart drops it, and any action on the results screen stops it (keys that do nothing there map to `Action::EndCelebration`). `pace.rs` is the pace caret (`pace` setting: `config::Pace` = off / pb / last / a wpm, written to TOML as a word or a number; `:pace`, `:set pace`, profile-able): pure `position(word lengths, elapsed, wpm)` → (word, char offset; the word's length means the space after it), `next_move_in` (what `poll_timeout` wakes on while a test runs on the typing screen) and `target_wpm` (from the history via `App::pace_target`, which uses the daily's language during a daily). `ui::typing` draws it as a `sub`-tinted background behind the character (`ghost_style`), under the real caret, and `pace 87` on the mode line; it never touches the engine, keylog or scoring. `misses.rs` counts the finished test's wrong characters (`Misses`, per character, kept in `Outcome`) and maps them onto a keyboard at draw time (`Misses::on(Keyboard)` → `KeyMisses`, `heat`, `layout`) for the `keys` results section; it never reads the keylog. Each run also stores its `missed_chars`/`typed_chars` in the `TestRecord` (schema 4, characters not keys), and the `:missed` screen (`Screen::Missed`, `ui::missed`) adds up counted runs in a `MissedRange` (`Misses::from_records`, cached in `App::missed`, rebuilt on `Action::ShowMissed`/`MissedStep`) and maps them onto the current layout at draw time, picking the biggest `misses::SIZES` key size that fits. Layouts are `config::Keyboard` (`src/config/keyboard.rs`: unshifted/shifted rows per layout, `key_for`; `keyboard` setting, `:keyboard`).
- HUD: the live readouts in the typing screen's top-left (`config::Hud` in `src/config/hud.rs`: the shown `HudItem`s in order, TOML `hud = ["timer", "wpm"]`, unknown names skipped on read so a synced config from a newer ttyp still loads; profile-able as one setting). `ui::typing::hud_line`/`hud_text` draw it (items: timer, wpm, raw, acc, errors; live and raw wpm read 0 for the first second; `poll_timeout` ticks every `TIMER_TICK` while a `ticks()` item other than the timer is shown, otherwise a running timed test wakes once a second, `App::clock_wake`). `:hud` opens `Screen::Hud` (`app/hud.rs`, `ui/hud.rs`: checklist in line order with a preview; space shows/hides, ←/→ moves an item along the line, every change saves at once); `:hud wpm [on|off]` toggles one directly.
- Error log: `src/errlog.rs` appends every error and warning to `Paths::log_file` (`ttyp.log` in the data dir; moved to `ttyp.log.old` past 256 KB), one line each: time, level, `[context]` tag, message. `main` calls `errlog::init` and logs panics and fatal errors; `App::report(context, msg)` logs and shows a notice (use it for real failures: file writes, network, downloads; plain `notify` for feedback on what the user typed); `errlog::warn`/`log`/`quiet` for entries without a notice. Startup warnings are all logged; the notice shows the first and how many more.
- State files: write through `config::write_atomic` (temp file, fsync, rename; keeps symlinks and mode) or `write_private` (0600, the token); read with `config::read_state`/`load_state`, which move a file that won't read or parse to `<file>.bad` instead of letting the next save overwrite it. Worker threads (`online::worker`, `catalog::worker`) run each request under `errlog::catch_panic`, so a panic still sends that request's error reply; the panic hook in `main` only logs panics off the main thread.
- Font problems: `gfx::load` rejects a font missing Latin letters (symbols/icon/emoji fonts, a collection's wrong face) with an error naming the file; with `font = ""` it falls back to the first bundled font and only logs. Other fonts get the first bundled font as a fallback face (`Face::add_fallback`); fontconfig matches carry their collection index (`Source::File(path, index)`), and a pattern's family (before `:`) must match. `Face` records characters drawn with no glyph (`take_missing`), and `App::report_font_problems` (each loop pass and after each draw) reports them once, plus a failed startup load.
- Update notice: `src/update.rs` (UI-free: `Version`, `Update::between` with `major` when the major number goes up, `Cache` in `Paths::update_file` = last check time + latest version, `due` after `CHECK_EVERY` = an hour, `Checker` asks `RELEASES_URL` (GitHub latest release; `TTYP_RELEASES_URL` at build time) on a thread, `how_to_upgrade` from the canonical exe path). `app/update.rs`: `start_update_check` shows the cached answer at once and checks if due, `drain_update` saves the answer; off when `server = ""` or `update_check = false` (config/`:set` only). `ui::splash::draw_update` draws `App::update` between the menu and the key line: one accent line, or a framed bold notice for a major release.
- Difficulty: `app/difficulty.rs` (`sudden_death`, `min_wpm` = `config::MinWpm`) ends a running non-daily test with `TestEngine::end_at` and records it with `Invalid::SuddenDeath`/`BelowMinWpm` (`is_failure`; results say "failed"); `poll_timeout` ticks while `min_wpm` applies. Network errors go through `online::net::explain` (offline vs a name that doesn't resolve vs refused/timeout/dropped).
- Custom word sets: rules in `ttyp_core::custom` (names, 5000 words, 40 chars, `addition` sorts typed words into new/duplicate/rejected); local files in `src/custom/` (`CustomStore`, `Paths::custom_dir`; `menu.rs` = `CustomMenu` page + `CustomEditor` with its y/n `pending`); `app/custom.rs`, `ui/custom.rs` (`Screen::Custom`, the install screen's third tab, and `Screen::CustomEdit`). `config.custom` replaces the language in `build_engine` and makes `language_key` `custom:<name>`. Server `crates/ttyp-server/src/custom.rs` (migration 0005; `GET /custom`, `GET /custom/{name}`, `POST /custom`, `POST /custom/{name}/install` counts one install per user, never the author, `.../unpublish`).
- Account sync (while logged in): configs and personal bests follow the account. Rules and the three-way merge in `ttyp_core::sync` (`Configs` = config name → TOML text, kept as text so newer settings pass through older clients, plus the `active` list; `Configs::merge(base, local, remote)`: each config/the active list takes the side that changed it, local wins clashes, no base = first sync, union with the server's copy and active list winning; `Best`). Server `crates/ttyp-server/src/sync.rs` (migration 0006; `GET`/`POST /sync/configs` stores the blob only if `base_rev` is current and always answers with the server's `ConfigSync`; `GET`/`POST /sync/bests` keeps the faster per mode+language and answers with all). Client `online/sync.rs` (`local_configs`/`write_configs` over `profiles/`, `Synced` = last agreed rev + configs in `Paths::sync_file`, `Bests` cache in `Paths::bests_file`, `missing` = local history bests the account lacks) and `app/sync.rs`: fetch at start, login, `:config` and every `PULL_EVERY` after input; `App::save_config` and profile saves call `configs_changed` (push if local ≠ base); a fetched or rejected-push reply waits in `pending_configs` until no test/daily is running and no config is being edited, then `merge_configs` sets base = server state, applies the merge (`apply_configs`: write files, reload registry, re-activate the active list; a config that fails to load is reported and kept in the list, never pushed as switched off) and pushes what differs. `App::best` = max(local history, `bests`) feeds `is_pb`, `pace::target_wpm` and `Summary::with_bests`. Logout (`forget_sync`) drops sync.json and bests.json.
- Missed words: `stats::missed_words::MissedWords` (per language key, top `MAX_WORDS` = 500 by misses then recency, `Paths::missed_words_file`). `app/practice.rs`: `note_miss` (after each `TypeChar`, a wrong key notes its word) and `flush_missed_words` (on finish, restart, rebuild, quit); `:pm` sets `App::practice` and `fresh_engine` builds an endless `Mode::Time(u16::MAX)` test from the top N (`PRACTICE_SIZES`, `Action::PracticeStep` on ←/→ while idle); difficulty is off in practice and practice runs never finish, so they aren't saved.
- utheme (macOS only, all behind `cfg(target_os = "macos")` incl. the `notify` dependency): `src/utheme_client.rs` is utheme's client protocol v1 with no app types (the same file is in ctui; keep them identical): `read_generation`, the `Watcher` thread (notify on `~/.local/share/utheme`, or its parent while it's missing, + 1 s readlink poll; a burst of events reads once; after each update it calls `wake_terminal`, a `SIGWINCH` to ourselves that crossterm delivers as a resize), `heartbeat`, `mix`, and `Client` (removes its heartbeat on drop). `src/app/utheme.rs` maps a `Snapshot` onto ttyp's roles; with `theme = "utheme"` `App::utheme_tick` starts/stops following (each event-loop pass and in `App::new`, before the first frame), `App::theme` prefers the live theme, and `utheme_wait` caps the poll at 1 s while following as a fallback for that wake (it isn't a `Tick`). `scripts/utheme-e2e.sh` checks it end to end against a fake utheme folder (CI runs it on macOS and Linux).
- `src/ui/` — rendering only; one file per screen (`leaderboard.rs`, `graph.rs` and `login.rs` are the online ones; `splash.rs` draws the landing logo in half blocks, shrinking to a text logo and dropping tagline then keys in small terminals; `results::render_chart` draws any per-second series; `results.rs` also draws the keyboard heatmap and the confetti, which only lands on blank cells away from text). `bigtext.rs` rasterizes the 4×6 pixel font (`font.rs`) into block characters for `fontsize` 2–16 when graphics are off or unsupported; `slider.rs` is the bottom-line numeric picker.
- `src/ui/widgets/` — list-screen building blocks: `Selection` (cursor + scroll window, no rendering), `SelectTable` (themed ratatui `Table` with column specs, cell roles, `›` marker, pinned row; columns grow to their content before `Min` columns share the slack, what still doesn't fit is cut with `…`, and the selected row wraps to show it whole), `panes` (side-by-side or tabs by width), `hints` (bottom hint line).
- `src/gfx/` — real-font text for `fontsize` 2–16 via the kitty graphics protocol. The `graphics` setting is config-file only (no command, not in profiles): `kitty` (default; `auto` is read as kitty) uses images when `detect` recognises the terminal, else blocks; `off` forces blocks. `raster.rs` draws one RGBA image per distinct glyph (char + colours) with fontdue; `kitty.rs` encodes upload/place/delete escapes; `fonts.rs` resolves the `font` setting (path, config `fonts/` dir, bundled font, fontconfig family). At startup the font loads on a thread (`Gfx::configure_in_background`, `FaceSlot`): the first frame only waits for it if it draws real-font text, and `take_load_error` hands a failure to the event loop as a notice; `:font` loads synchronously (`configure`). The `:font` completions (`fc-list`) are listed on first use (`Completions::fonts`). `typing::render` returns `ImageLine`s; `App::draw` hands them to `Gfx::present` after ratatui draws, inside a synchronized update. `present` diffs placements by pixel position, so a keystroke only moves a few placements; images are purged when size/font/cell size change and after a resize (the terminal clear frees them), but each glyph's encoded upload is kept per pixel size and font (`Gfx::encoded`, up to 8 MB), so a resize resends without rasterizing again.

Images can't be seen in tmux. To check graphics output, run ttyp under a pty that reports pixel sizes (`TIOCSWINSZ` with xpixel/ypixel, `TERM=xterm-ghostty`), then replay the `ESC _G` commands: `a=t` uploads (base64 → zlib → RGBA), `a=p` placements at the preceding cursor position plus `X`/`Y` pixels, `a=d` deletes.

## Conventions

- Every state change goes through `App::dispatch(Action)`.
- Engine methods that depend on time take an `Instant` (`*_at`) so tests are deterministic.
- Config changes are saved immediately via `App::save_config`.
- Building a list screen: keep a `widgets::Selection` in the screen's state and move it from `App::dispatch` (`move_by`, `page`, `home`, `end`); in `src/ui/<screen>.rs` build `Column`s and `Row`s of `Cell`s with a `Role`, render them with `SelectTable::new(&columns, rows, &selection)` (`.pinned(i, row)` keeps a row on screen, `.focused(false)` hides the marker), use `panes::split` for side-by-side tables and `hints::render` for the key line. The profile list (`src/ui/profiles.rs`) is the reference. Every selectable list looks the same (owner's decision, 2026-10-01): the selected item gets the ` › ` marker, moves one column right and takes `Palette::selected`. `SelectTable` does this itself; a hand-drawn list uses `widgets::cursor::lead` and `cursor::style`, never its own marker.
- Adding a leaderboard: one `BoardSpec` in `ttyp_core::boards::BOARDS` (a new `Period` or rule also needs a `Scope`/filter in `crates/ttyp-server/src/leaderboard.rs`); rebuild the server.
- Adding a command: add a `CommandSpec` to `COMMANDS`, a `Command` variant, a `parse` arm, and an `App::execute` arm.
- Adding a HUD item: a `HudItem` variant (`name`, `label`, `about`, `parse` aliases, `ALL`, and `ticks` if it changes between keys so `poll_timeout` redraws on a timer) and its arm in `ui::typing::hud_text`; the menu, command, config and profiles pick it up.
- Adding a setting: add the field to `Config` and `ProfileSettings`, and a line to `settings!` in `src/profile/mod.rs` (plus `Editor::cycle` for its ←/→ behaviour).
- Font sizes: `FontSize` wraps a block set + scale; `fontsize` levels 1–16 are a fixed ladder (`from_level`), while fullscreen (`FontSize::fit`, called from `App::typing_frame`) searches every set/scale.
- Numeric settings use `ArgKind::Slider`: `Command::X(None)` opens the slider (`App::open_slider`), `Some(n)` sets directly.
- Adding a theme or language: put it in `catalog/themes/` or `catalog/languages/` and run `TTYP_BLESS=1 cargo test catalog_index` to regenerate `catalog/index.toml` (the test fails while it's stale, and if an entry shadows a built-in). Built-ins are kept to the fallbacks; adding one means `assets/…`, `include_str!` in `BUILTIN` and its name in `BUILTIN_NAMES`.
- Adding a bundled font: put `<slug>-latin.ttf`, `<slug>-latin-ext.ttf` and `<slug>.LICENSE` in `assets/fonts/` (Fontsource: `cdn.jsdelivr.net/fontsource/fonts/<slug>@latest/<subset>-400-normal.ttf`) and a `bundled!` line to `BUNDLED`.

## Releasing and deploying

How 1.0.0 shipped; repeat in this order. Credentials (Cloudflare API token, tunnel
token, crates.io token) live only in `~/Projects/ttyp-private/`, `.env` and the shell;
the public hostname is in `src/config/mod.rs` by the owner's decision.

1. **Green on `main`.** Feature work lands on a branch, then fast-forward `main`
   (`git merge --ff-only`). Before pushing anything run the secret checks at the bottom
   of the private deploy notes (`git diff --cached | grep …`, `git log -p | grep …`).
2. **Version, tag, GitHub release, Homebrew tap:** `scripts/release.sh patch|minor|major`
   (needs `gh` logged in and `../homebrew-ttyp` cloned and clean). It bumps the root
   `Cargo.toml` (only the `ttyp` version; bump `crates/ttyp-core` by hand and the
   `ttyp-core = { version = … }` lines in both dependents when core changes), runs the
   tests, tags `vX.Y.Z` and creates the release. The tag push runs
   `.github/workflows/release.yml`, which builds static binaries for macOS arm64/x86_64
   and Linux musl arm64/x86_64 and attaches them with `.sha256` files; the script waits
   for that run, then regenerates `Formula/ttyp.rb` in the tap from those checksums (so
   installs download a binary, no Rust) and pushes it. `--HEAD` still builds from source.
   Run the workflow by hand (`gh workflow run release.yml`) to check the builds without
   publishing. Users get it with `brew update && brew upgrade ttyp`; Homebrew 6+ first
   needs `brew trust andples/ttyp`.
3. **crates.io:** `cargo publish -p ttyp-core`, then `cargo publish -p ttyp` (cargo waits
   for the index in between). Needs `cargo login` with a token that has publish scopes
   and a verified email on the account. `ttyp-server` is `publish = false`. Package
   contents are pinned by the `include` lists in each `Cargo.toml`.
4. **Server image and stack** (owner's machine): `docker compose up -d --build` from the
   repo root builds `crates/ttyp-server/Dockerfile` and starts `ttyp-server`,
   `ttyp-backup` and `cloudflared`. `.env` (mode 0600, git-ignored) holds
   `TUNNEL_TOKEN`; `.env.example` shows the shape. The tunnel, its ingress and DNS
   record were created once with the API calls in the private deploy notes and don't
   need redoing for a rebuild. Check with `docker compose ps` (server healthy) and the
   public `/health` URL from the private notes. Backups, restore and logs:
   `crates/ttyp-server/README.md`.
5. **Client builds for another server:** set `TTYP_DEFAULT_SERVER` and
   `TTYP_DEFAULT_GITHUB_CLIENT_ID` in the environment of `cargo install --path . --locked`.
   Homebrew and crates.io builds use the built-in public server.

Compatibility to keep across releases: the wire format in `ttyp-core/src/api.rs` and the
keylog (`Key` serde shape), the `daily_schedule`/`results`/`starts` schema (migrations only
add), and `TestRecord::SCHEMA` (old history lines must keep parsing). Daily attempts: the
first keystroke calls `POST /dailies/{id}/start`, the submission carries its `start_id`
(optional on the wire, so pre-1.2.2 clients still submit), and the first-try board needs
`first_eligible = 1` (a start, or a row from before starts existed). The server needs
rebuilding whenever `ttyp-core` changes (replay, word lists).
